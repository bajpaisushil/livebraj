# Data sources, licensing and provenance

Every piece of world data in this project is traceable to a source that permits
this use. This document is the record.

---

## 1. Geographic data — OpenStreetMap

**Source.** OpenStreetMap, retrieved through the public Overpass API.

**Licence.** Open Database Licence (ODbL) 1.0.

**Extract.** Bounding box `27.5300, 77.6300` to `27.6300, 77.7400`, covering
Vrindavan and its surroundings in Mathura district, Uttar Pradesh.

**What we take.**

| Query | Result | Used for |
|---|---|---|
| `way[highway]` | 1,840 ways → 1,055 in bounds | the entire road network |
| `way[waterway] / [natural=water]` | 35 | the Yamuna, Brahma Kund |
| `[amenity=place_of_worship]`, `[historic]`, `[tourism]` | 140–178 | landmark coordinates |
| `way[building]` | 176 | *not used* — coverage is too sparse |

Raw responses are cached under `tools/osm-import/raw/` so the import is
reproducible without re-querying Overpass.

**Obligations we meet.**

- Attribution is displayed in the client's main menu: *Map data © OpenStreetMap
  contributors (ODbL)*, and stated here and in the README.
- The generated content modules carry the attribution in their file header.
- ODbL share-alike applies to the derived *database*. The generated files under
  `client/src/content/*.generated.js` are that derived database and are
  distributed under ODbL. Game code, art and text are separate works.

## 2. What OpenStreetMap does not give us

A map knows where a temple is. It does not know what it looks like, who is
worshipped there, or why anyone walks to it. Those are authored:

| Data | Where | Basis |
|---|---|---|
| Architecture, footprint, height, colour | `tools/osm-import/config.mjs` | published photographs and architectural descriptions of each temple |
| Deity and available interactions | same | temple tradition |
| District polygons and palettes | same | the town's actual built character |
| Stories | `client/src/content/stories.js` | see §3 |
| Vegetation and flower placement | `client/src/content/flora.js` | generated by rule from the imported geometry |

Where OSM has no node for a landmark, a curated fallback coordinate is used and
the importer reports it. Currently 20 of 23 landmarks match a real OSM node;
3 use a fallback (`loi-bazar`, `vrindavan-gate`, `chandrodaya`).

## 3. Story content

**Editorial rules, enforced in `stories.js`:**

1. Nothing is invented.
2. Where an account is traditional rather than historically documented, the text
   says so in its own words — "by tradition", "it is told".
3. Dates and attributions are the widely published ones. Anything uncertain is
   phrased as uncertain rather than stated flatly.
4. Every entry carries a `source` field, shown at the foot of the story card.

Sources in use: Archaeological Survey of India records and published
architectural surveys; temple trust records; the Bhagavata Purana (Canto 10) for
the episodes associated with the ghats; and Gaudiya Vaishnava tradition, labelled
as tradition.

Content is deliberately isolated from game logic so it can be corrected,
reviewed by people who know the subject better, translated, or replaced without
touching a single system.

---

## 4. What we deliberately do not use

**Google Maps data, imagery, tiles or Places content.** Its terms forbid
derivative datasets and scraping, and building a world from it would make the
project undistributable. OpenStreetMap carries the same real road geometry for
Vrindavan under a licence that permits this, which is why the world is built
from it instead. The result is the same precision without the legal exposure.

**Copyrighted photographs of temples** for textures or reference geometry.

**Scraped devotional text** of uncertain provenance.

---

## 5. Assets

There are none. No image files, no audio files, no 3D models, no video.

- Geometry is generated procedurally at load time.
- Textures are `CanvasTexture` drawn in code.
- Audio is synthesised with the Web Audio API — including the temple bell, which
  is an inharmonic additive stack rather than a sample.
- The only external resource is Google Fonts (Yatra One, Marcellus, Spectral,
  Jost, Tiro Devanagari Hindi), each under the SIL Open Font Licence.

This keeps the download small, removes every asset-licensing question, and means
the experience works fully offline once loaded.

## 6. Refreshing the extract

```bash
# Overpass is rate-limited and often busy; retry across mirrors.
node tools/osm-import/import.mjs
```

Re-run whenever the source extract is refreshed or `WORLD_HALF` changes.
The generated files are committed so a clean checkout needs no network access.
